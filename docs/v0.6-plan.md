# MEW v0.6 — "gbrain, working" · release plan

v0.5 made MEW **the daily companion**. But in daily use the memory doesn't earn its keep:
you repeat yourself constantly, and gbrain shows near-zero benefit. **v0.6's headline is
making gbrain the operative spine** — memory that learns from what you *do* (not just what
you say), applies it *deterministically* at placement, stays reliable and local-first, and
is *visible and correctable*. Around that: the live-bug fixes daily use surfaced, and the
release-hardening that gets all of this onto people's machines.

**Diagnosis (why gbrain feels dead today, from the code):** it learns only when you STATE a
rule and the model catches it — nothing learns from repetition; recall is framed as
advisory color ("informs; the live week decides") that binds nothing; where prefs do apply
it's a soft 0.25 scorer nudge on duration/tag only; and it's often off (no web sidecar,
#249 disconnects) with no surface showing what it knows. v0.6 fixes each.

Working branch: `v0.6-rc` (cut from `main` @ v0.5.0). Merge feature PRs into `v0.6-rc`;
promotion PR `v0.6-rc → main` runs the heavy gates; tag `v0.6.0` cuts installers.
Standing laws unchanged: chat-first, positive-only voice, tools are the only week-mutation
path, keys never leave the device, graceful keyless/brainless degradation. Merge bar
unchanged: plain Approve, zero 🟡, gate proof in the PR body.

## Tier 0 — live-bug fixes (jump the queue)

From a real packed release-day transcript (v0.5) where MEW got "stupid on some things."
The day-load meter behaved (flagged 11½h vs a 5½h usual); these four did not.

- **#323 · Meals stay sane under packing/reshape** — the circadian anchors (#298) only
  engage through the scorer; a model `plan_blocks` reshape with explicit times bypasses the
  window + inter-meal gap, so it placed **dinner 2h after a 4pm lunch** ("are you stupid?").
  A pure domain guardrail corrects/relocates meal-classified placements regardless of path.
- **#324 · Own-vs-own collision drift** — MEW placed the pushes overlapping lunch/dinner/an
  errand and asked *after*. Rescue (#286) is external-only; the user's own flexible blocks
  should drift out of the way as work lands, not sit overlapped pending a question.
- **#325 · Reshape without flailing** — corrected on dinner, MEW emitted five "you're
  right/good catch" messages and repeated slot-finds to move one block. One acknowledgment,
  one sweep (its own "reshaping is one sweep" rule, enforced).
- **#326 · protect-rest nudge copy** — fired twice with a garbled doubled-title template
  ("X lands on your grocery pickup… the grocery pickup… is yours — keep it?"). Clean copy + dedup.

## Tier 2 — make v0.5 reach users (release hardening)

These are the difference between "tagged" and "landed on people's machines." Highest
priority because everything v0.5 shipped is gated behind them.

### A · Self-updater signing infrastructure — **M** (#167)
`createUpdaterArtifacts` is `false`, so v0.5 ships as downloadable installers + a GitHub
Release, but existing installs **won't auto-update**. Wire the Tauri updater signing keys
(CI secrets: `TAURI_SIGNING_PRIVATE_KEY` + password), flip the flag, publish the
`latest.json` + `.sig` artifacts on tag, and verify the in-app updater (already wired in
`lib.rs`: check-on-launch → `mew://update-ready` → `apply_update`) pulls a real update.
**Accept:** a tagged release produces signed updater artifacts; a prior-version desktop
build detects and applies the update through the existing in-app flow.

### B · Streaming: confirm the ~300 ms target on a live key — **S** (#281 tail)
The streaming rework shipped with the paint pin and an honest activity state, but the
"first visible output within ~300 ms of the API's first chunk" AC was deferred to live
measurement (no key in the build lane). The dev timing line (`model/stream-timing`) is the
instrument. Measure on a real Anthropic key; if the pre-reply gap is still long, adopt the
wire-pinned effort knob (`providerOptions.anthropic.effort`) for conversational turns —
**only if** the #102 planning pin (a day placed in ≤2 tool rounds) stays green.
**Accept:** measured first-visible ≤ ~300 ms documented; effort knob adopted or explicitly
declined with the measurement behind the call.

### C · Trim the entry chunk back under budget — **S/M**
v0.5's release raised the `main` budget 330→370 KB for the eager UI (plan-mode picker,
onboarding v2, tray/settings rows). Reclaim it: lazy-load onboarding (first-run only) and
the picker (only when planning), then lower the budget back toward 330.
**Accept:** onboarding + picker are dynamically imported; `main` chunk back under 340 KB
with the budget lowered to match; first-run and plan flows unchanged.

## Tier 0.5 — calendar command surface (from live use; grows every RC)

MEW is "incapable of making simple changes without clearing the entire day." A 12-turn
transcript failed three trivial edits because MEW **couldn't see the calendar, couldn't
delete a done block, and kept editing the wrong one.** Standing directive: *give it every
ability, even granular ones, and keep adding some every RC.* This is the ongoing track.

- **#333 · `list_blocks` — eyes on the calendar** (urgent): an itemized readout (exact name
  + time + tag + status + a targetable handle) and a keyless "show me today." The root
  enabler — MEW was editing blind. *Likely first.*
- **#334 · Surgical single-block edits** (urgent): precise **name+time** targeting ("check
  name and timestamp both always"), a rename touches only that block (no day-clearing, no
  cascade), ambiguity asks via chips, and **explicit delete/rename of a done block works**
  (the mew-protection law lifts for explicit single-target intent, keeps guarding bulk ops).
- **#335 · Granular ops** (the standing track): split / merge / duplicate / resize / batch /
  relative-move — each a small first-class tool through the one mutation path. Ship what
  fits each RC; keep a "next candidates" list here. *This section grows every release.*
  - **Shipped this RC (rc.1):** three cohesive single-target ops, each a tool def +
    keyless route + executor through the one mutation path, reusing #345 targeting
    (`findTarget`/`resolvePrecise`) and #350's recurring scope — no re-implemented targeting,
    no second door. External/fixed blocks respected by all three (never moved or split-over).
    - **resize** (`resize_block`) — change a block's length keeping its start, absolute
      (`durationMin`) or relative (`deltaMin`, e.g. "make the deck 30 min longer"); a
      duration-only edit, so it routes through the edit path and inherits its recurring-scope
      chips. Keyless fixes the named-relative gap ("30 min longer" no longer mis-reads as an
      absolute 30).
    - **duplicate** (`duplicate_block`) — copy a block to another day/time ("duplicate the
      deck to friday"); the original stays put, the copy is a fresh owned block, and a
      `recurrence` makes the copy a repeating series (#159). Cross-day keeps the source clock;
      same-day lands in the next free slot. An external event copies into an owned block; the
      calendar original is untouched.
    - **relative-move** (`move_relative`) — nudge without an absolute time: `earlier`/`later`
      (default 30 min), `next_day` (same clock, one day on), or `next_free` (the soonest clear
      slot from now, via the pure `week.nextFreeSlot`, always clear of fixed/external).
  - **Next candidates (higher-risk, deferred):** **split** (rescue-split-as-a-first-class-tool,
    #286), **merge** (combine adjacent same-tag blocks), and **batch** (one op over many
    targets — needs the `offer_choices` wide-blast confirm for blast-radius consent). Pick up
    per this same tool + keyless-route + executor recipe next RC.

## Tier 1 — gbrain, working: the memory that learns you (the v0.6 marquee)

Make gbrain the operative spine. Interaction model throughout: **offer once, then remember
forever** — MEW notices a pattern, asks a single chip the first time, and after you confirm
it just does it (silently, undo one tap away). Four pillars:

- **#327 · Learn from doing** — form task rules from repetition. Block "the deck" as 90-min
  deep-work in the morning a few times and MEW offers *"want me to just do that?"* — confirm
  once, never restate again. Deterministic frequency+variance over local memory, not a stated
  rule the model has to catch. *The heart of "stop repeating myself."*
- **#328 · Deterministic apply** — a confirmed rule prefills the **full spec** (duration, tag,
  timing window, attention, recurrence) on **every path incl. keyless**, before placement —
  not a soft 0.25 nudge on duration/tag. "add the deck thursday" just lands right.
- **#329 · Reliable + always-local** — the learn→apply loop works fully **brain-off**
  (on-device memory is the floor; the gbrain graph enriches on top), the sidecar self-heals,
  and status reads honestly. Absorbs the #249 tail. No more "zero benefit because it's off."
- **#330 · Memory console** — a "what I know about you" surface: task rules, your rhythm,
  standing prefs — each visible, editable, forgettable. So you can see it working and steer it.

**Folded in as facets** (same learn/apply machinery, not parallel paths):
- **#321 · Energy-aware scheduling** — Pillars 1+2 applied to *where* deep work / admin land
  (learned band × task-type; admin batched; NOT a textbook curve — you code on low energy).
- **#322 · Estimate correction** — Pillars 1+2 applied to *durations* (per-tag run-long).
- **#320 · Conversational multi-turn editing** — the *within-session* sibling ("move it
  earlier", "the one after lunch"), keyless too. Adjacent memory, kept on its own.
