# MEW v0.5 — “the daily companion” · release plan

v0.3 made MEW smart (AI-SDK model layer, recall, chips). v0.4 made it **trustworthy**
(self-healing two-way sync, honest previews, a dial that reads, a desktop app that ships).
**v0.5 makes MEW the thing that actually runs your day** — desktop-native presence,
daily rituals, and the intelligence layer that earns its keep every morning.

Working branch: `v0.5-rc` (cut from `main` @ v0.4.0). Merge feature PRs into `v0.5-rc`;
promotion PR `v0.5-rc → main` runs the heavy gates; tag `v0.5.0` cuts installers.
Every item below follows the standing laws: chat-first, positive-only voice, tools are
the only week-mutation path, keys never leave the device, graceful keyless degradation.

---

## From live testing — chat feel (jump the queue)

Found by the user in daily use on v0.4.0. These define how alive the app feels; start here.

### 1 · Type while MEW works — **S/M**
The composer locks while a turn streams — you sit on your hands mid-thought. Never lock it:
typing during a turn is always possible; Enter queues the message (sent when the turn settles)
or offers stop-and-send. The stop affordance stays.
**Accept:** keystrokes land in the composer at any turn phase; a queued message sends exactly
once; stop-and-send preserves the partial reply per the existing "(stopped — what's above
stands.)" contract.

### 2 · Real streaming, not cosmetic — **M**
Replies feel like a long stall then a paste, though the model is faster than that. Two suspects
to run down: **(a)** Sonnet 5 runs adaptive thinking by default — silent pre-reply thinking
delays the first visible token even with `showReasoning` off (consider requesting lower
`effort` for conversational turns, and show a live "thinking…" state instead of dead air);
**(b)** render batching — check whether the store/UI coalesces deltas and only paints on
completion. Fix = paint deltas as they arrive + honest activity states.
**Accept:** first visible output (token or activity state) within ~300 ms of the API's first
chunk; an e2e pin observes ≥3 distinct growing paint states on a long reply; no regression to
the step-cap pause copy.

### 3 · Tool-call renders — MEW showing its hands — **M**
Tool calls are invisible today: MEW places three blocks and the chat shows only prose. Render
each call as a small MEW-styled activity card in the reply stream — icon + verb + target
("holding thursday 9–12", "syncing your calendar"), live shimmer while running → ✓ when done,
collapsible for multi-step turns. The transcript becomes a receipt of what actually changed.
**Accept:** every executor tool call renders exactly one card with a settled state; failures
render honestly (MEW-voiced, never a stack trace); cards replay correctly from persisted chat
on reload; shoot gains a canonical shot of a multi-tool turn.

## Headliners

### 4 · System tray companion (desktop) — **L**
The app you never open because it's already there. Tray icon shows a subtle state dot;
hover = current block + time remaining; click = quick-capture popup; menu = *start next /
done / open MEW*. Closing the window minimizes to tray, and the hourly calendar sync keeps
running while hidden.
**Accept:** window closed ⇒ sync tick still fires (verify ledger timestamps); tray tooltip
matches the dial's focus block within 1 min; quick-capture from tray lands in the rail.

### 5 · Morning brief & evening wrap — **M**
The discipline habit loop. At day-start (configurable, default 8:30) MEW posts a 3-line
brief in chat — today's shape, the first block, the one risk — mirrored as a native
notification (click lands on it). At day-end, a positive wrap: what got done, what rolls
forward, one kind observation from insights. Never a guilt list — rolled items are
"waiting", not "failed".
**Accept:** brief fires once per day even across restarts (persisted last-fired key);
keyless mode still produces both from the rules floor; quiet-hours respected.

### 6 · Rescue my afternoon (conflict re-planning) — **M**
The pull already detects when an inbound meeting lands on planned work — today it just
overlaps silently. Now MEW says so in chat and offers `offer_choices` chips: *shift the
block / split around the meeting / roll it to tomorrow*. One tap re-plans via the normal
tool path.
**Accept:** simulated inbound event overlapping a work block produces exactly one chat
nudge with ≥2 viable chips; choosing one mutates the week through the executor and syncs
out on the next run.

### 7 · Weekly planning ritual — **M**
Sunday evening (or on demand: "plan my week"): MEW pulls the calendar, lays deep-work
blocks around the fixed meetings using your best-hours insight, asks 2–3 chip questions
(top priority? protected morning? gym days?), then places the week in one pass.
**Accept:** a seeded week with 12 meetings produces a plan with zero overlaps, honors
realistic-best hours, and completes in ≤2 tool rounds (#102 budget).

## Strong seconds

### 8 · Insights card — show the science — **S/M**
`domain/insights.ts` already computes follow-through by time band, weekday load, and
carry patterns — nothing surfaces it. A weekly card in Settings (or a `show insights`
chat reply): best deep-work hours, kindest day shape, one habit observation. Positive
voice only.
**Accept:** card renders from local memory alone (no brain, no keys); every claim
traceable to an insights.ts function with a unit pin.

### 9 · Global quick-capture hotkey (desktop) — **S**
⌘/Ctrl+Shift+C works inside the app; register it as an OS-global shortcut via the Tauri
plugin so a thought mid-email becomes a capture without switching windows.
**Accept:** hotkey fires with MEW hidden; capture appears in the rail; collision with an
existing OS binding degrades gracefully (setting to rebind/disable).

### 10 · Notification actions — **S**
Native nudges grow two buttons: *done* and *+15 min*. Both route through the existing
executor tools; the toast copy stays MEW-voiced.
**Accept:** clicking *done* completes the block (memory event logged); *+15* shifts it
and re-syncs; falls back cleanly on platforms without action support.

### 11 · Onboarding v2 — the first five minutes — **M**
We lived the rough edges this week: key setup, client-ID hunting, redirect URIs, matrix
chips. A guided first-run: paste keys (with test buttons) → connect calendar (loopback
explained, URIs copyable) → one guided "plan today". Every step skippable, everything
works keyless-degraded.
**Accept:** fresh profile → planned day in ≤5 min without leaving the app except for the
Google consent screen; each step has a "later" path that leaves no broken state.

## From UX research (added mid-flight · night shift 2026-07-15)

Patterns pulled from the current daily-planner field (Sunsama, Akiflow, Motion, Reclaim,
Notion Calendar, Vimcal teardowns) and filtered hard against MEW's laws — only what the
chat-first, positive-only, keyless-degradable shape can carry honestly. Rituals, rescue,
and tray presence were already ours (items 4–7); these three weren't:

### 12 · Honest day-load meter — the overcommit guard — **S/M**
Sunsama's core insight: people don't fail their plans, they overbook them. MEW already
computes booking honesty (`insights.estimateFactor`, lateness) — surface it AT PLAN TIME:
when a day's placed work exceeds the user's demonstrated daily throughput (not a generic
8h), MEW says so in chat while placing ("that's 6h of deep work against your usual 4½ —
want me to keep it kind?") and the week view carries a quiet per-day density cue. Never a
red bar, never "overloaded" — a kindness meter, insights-backed.
**Accept:** placing past the throughput line produces exactly one gentle chat line +
`offer_choices` (keep it / trim it); density cue renders from local memory alone; voice
pin ({overloaded, behind, too much} absent); zero nagging on days under the line.

### 13 · Breathing room — meeting buffers — **S/M**
The Fantastical/Reclaim staple MEW can do kinder: a configurable prep/decompress buffer
(default 10 min, settable per calendar) that the scheduler honors around synced external
meetings — deep-work blocks land shy of a meeting's edges, and back-to-back inbound
meetings get the gap named in the day's shape ("two meetings back-to-back at 14:00 — I
kept your half-hour after free"). External events never move (law); only MEW's own
placements respect the buffer.
**Accept:** with a 10-min buffer set, `plan`/`suggest_slots` never abut an external
meeting; back-to-back inbound pairs surface one observation line max per day; buffer=0
reproduces today's behavior byte-for-byte (default-off migration).

### 14 · Keyboard-first week — move blocks without the mouse — **M**
The pattern every praised calendar shares (Vimcal, Notion Calendar, Akiflow): full
keyboard speed. MEW's week view gets: focus a block (arrows between blocks), nudge it
(Shift+arrows, 15-min steps / day hops), resize (Alt+arrows), all through the SAME
executor path as drag — announcements ride the existing a11y grammar, `?t=` determinism
holds for shots. Complements the dial's arrow nav (#253) and the a11y gate.
**Accept:** a seeded week is fully re-plannable mouse-free (e2e run proves move+resize+
day-hop); every mutation goes through the executor (no direct state writes); focus ring
+ SR announcements pass the a11y shoot gate; drag behavior unchanged.

## From live use — plan mode (added mid-flight · night shift 2026-07-16)

### 15 · Plan mode — scenario previews for the big asks — **L** (ships as 15a + 15b)
Braindump a week ("deck, demo prep, three gym sessions, budget review…") and today MEW
places it in one pass — powerful, but at the moment of biggest consequence you get one
take and no say. **Plan mode** gives the big asks a manual gear: MEW classifies the
message first (tasks, tags, durations from your own demonstrated medians), then lays out
2–3 **named placement scenarios** — *protected mornings / spread even / front-loaded* —
as compact mini-week cards right in the stream: per-day strips, a rationale line each,
the day-load cue from item 12. Pick one, and exactly that plan lands.

The audit says the hard parts are already bought: `scheduler.candidateSlots` yields
conflict-free candidates by construction (fixed/external/optional excluded — previews
honest for free), `scoreSlots` takes a `ScoreWeights` profile — **a scenario IS a weight
profile** — and every candidate carries a human `why` string for the card's rationale.
`parse.inferTag` + `insights.taskDurations`/`bestBand` cover classification and
personalization. Chips (#254) define pick-liveness; tool cards (#282) define structured
rows that persist and replay.

The two laws that shape it: scenarios are **chat-only data** (a `propose_scenarios` tool
that mutates nothing, like `offer_choices`); the pick applies the stored, validated
places **byte-exactly through the executor** — a preview is a quote, never re-derived
through a second model pass. A scenario the week has since outgrown parks inert
(chips-style) and offers a fresh look instead of lying.

- **15a · scenario engine (domain)** — `domain/scenarios.ts`: task specs → K scenarios
  (distinct weight profiles + a best-hours profile when insights exist), validation
  against the live week, rationale lines. Pure, keyless-identical, fully tested.
- **15b · propose + pick (tool → UI)** — `propose_scenarios` tool; scenario cards
  (SSR-testable, replay-safe); exact-apply via the executor; entry points: explicit
  ("plan my week", "plan mode") and auto-offer when one turn would place ≥3 new blocks;
  a Settings row to tune/disable the auto gear. Rules floor generates the same scenarios
  deterministically — plan mode works with zero keys.

**Accept:** a 6-task braindump yields ≥2 valid scenarios, zero overlaps with
fixed/external blocks; the picked scenario lands byte-identical to its preview (pinned);
keyless produces the same picker; a stale scenario refuses kindly and offers a re-plan;
generation stays read-only and the apply is one executor call (#102 budget intact).

### 16 · Fed and paced by default — the sustenance layer — **S/M + M** (16a + 16b, from live use)
Two forces straight from daily testing. First, the silly placements: *"lunch's at
15:30–16:15, dinner at 17:00–18:00"* — the scheduler has no idea what a meal IS
(`preferredWindow` only knows work→morning), so a lunch ask lands in whatever free air
exists. Second, the repetition: every morning the same "I need lunch and dinner and some
breaks" instruction, for a layer of the day that should simply be there.

- **16a · circadian anchors (the root fix, domain-only)** — a meal-class recognizer in
  the scheduler's own scoring path: breakfast / lunch / dinner / snack-coffee-break
  titles carry research-grounded default windows (lunch 12:00–14:00, dinner 18:30–20:30,
  breakfast 7:00–9:30; snacks mid-morning / mid-afternoon), overridable by a remembered
  `time-default` pref ("lunch at 13:00", said once). Out-of-window candidates score near
  zero — a packed day can still force one, but never silently prefer one — and a
  meal-adjacency term keeps dinner a real stretch after lunch (never 45 minutes). Lives
  in `preferredWindow`/`scoreSlots`, so chat asks, tools, AND plan-mode scenarios (15a)
  all inherit sanity with zero store changes.
- **16b · the standing scaffold (kill the morning ask)** — rides the ritual machinery
  (#297's once-per-day key): each morning, if the day holds no meal-class blocks, MEW
  places lunch + dinner (+ paced breathers via the existing `restInsertion` pass, run
  over the whole day shape) around what's already there — through the executor, like
  every mutation — then says one line: *"fed and paced: lunch 12:30, dinner 19:00, two
  breathers — say the word to reshape."* Settings: on by default with kind defaults,
  per-meal windows/durations, off-switch; prefs personalize. Meals auto-placed are
  unprotected rest/private blocks — reshapes absorb them, rescue (#286) never treats
  them as displaced work, and they are never mews.

**Accept (16a):** the quoted transcript cannot reproduce — a free-day "lunch and dinner"
ask lands lunch 12:00–14:00 and dinner 18:30–20:30 (pinned); a packed-noon day places
lunch late only when nothing in-window fits (and the reply names the time); prefs
override windows; scenarios inherit (a braindump with "lunch" anchors it).
**Accept (16b):** a fresh morning with no meal blocks gains lunch + dinner + ≥1 breather
once, through the executor, exactly once per day across restarts; a day already carrying
a lunch block gains nothing; off-switch restores today's behavior byte-for-byte; keyless
identical.

builds the render layer 2's activity states reuse. Tray (4) and hotkey (9) share the Tauri
plumbing — pair them. Brief/wrap (5) before weekly ritual (7): the ritual reuses the brief's
compose + notification path. Rescue (6) is independent and highest
daily-delight-per-line-of-code. Insights (8) unblocks the wrap's "kind observation".
Onboarding (11) last — it demos everything the others build.
